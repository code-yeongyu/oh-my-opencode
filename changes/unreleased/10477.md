**Changelog entries now live in per-PR fragments.** A PR that changes user-facing paths adds exactly one file, `changes/unreleased/<pr-number>.md`; only the release workflow may edit `CHANGELOG.md`, and it assembles the fragments into the release section and deletes them. The gate rules are one reviewed module (`script/changelog-gate-rules.ts`) shared byte-identically across every repository we ship from, with each repo's only difference a small config file.
